LocalGuard

A small, transparent privacy extension for Chrome and Microsoft Edge.

No subscription or account. Everything runs inside your browser. This is a personal, manually installed extension with a limited tracker list, not a complete replacement for commercial security suites.

Install in Chrome

  1. If using the ZIP, right-click it and choose Extract All. Keep the extracted folder somewhere permanent. You can also use the supplied LocalGuard folder directly.
  2. Type chrome://extensions in Chrome’s address bar.
  3. Turn on Developer mode in the top-right corner.
  4. Choose Load unpacked, then select the LocalGuard folder containing manifest.json.
  5. Open the puzzle-piece Extensions menu and pin LocalGuard. Open its shield icon to check settings.
  6. Reload websites that were already open.

Install in Microsoft Edge

  1. Type edge://extensions in Edge’s address bar.
  2. Turn on Developer mode in the sidebar.
  3. Choose Load unpacked and select the same LocalGuard folder.
  4. Use the Extensions menu to show LocalGuard on the toolbar, then reload open websites.

Install separately in each browser. Their settings are separate. This build targets Chromium 121 and later; it is not packaged for Firefox, Safari, or mobile browsers. Browser policy on a managed work computer may prevent manual installation.

Version 1.2: maintained lists and protection test

Open LocalGuard and choose Tracker updates & protection test. EasyPrivacy coverage is enabled by default, alongside the original built-in rules. The bundled snapshot contains 44,310 domain-wide blocking entries and 558 compatible website exceptions. Third-party requests only are blocked; direct visits are preserved. This is a subset of EasyPrivacy: path-specific and other unsupported blocking filters are omitted. Compatible exceptions can also allow requests that the built-in tracker rules would otherwise block; optional cookie-header filtering remains separate.

Automatic updates: LocalGuard checks whether an update is due each hour while the browser is running and downloads at most once per 24 hours automatically. It uses the fixed HTTPS address EasyPrivacy distribution server. You can turn updates off or check manually. Downloaded files contain filter data, never executable code. They are checked for format, size, supported exceptions, version, unexpected large reductions, and browser-rule validity. A failed update preserves the current working rules and displays the error on the updates page.

Rollback: After a changed list is installed, the previous snapshot is saved. Restore previous version restores it and turns automatic updates off. You can turn updates back on when ready. A repeated download of an identical list does not overwrite rollback history. Source version, skipped-filter count, last check, and SHA-256 are shown. The hash identifies the download; it is not a publisher signature.

One-click test: Choose Run protection test. LocalGuard checks the installed rule set against saved settings and asks the browser engine to evaluate controlled examples for tracker blocking, navigation cleanup, direct visits, POST forms, known fingerprinting endpoints, and cookie filtering. Disabled features appear as Off. It is a local browser-rule simulation with no test network requests or changes to your settings. It does not prove every real website is protected or measure fingerprint anonymity. Use the activity log for evidence of actual browsing actions.

Updating from 1.0 or 1.1: Replace the files in the same loaded LocalGuard folder, click Reload on the browser’s Extensions page, and accept an added permission if prompted. The added alarms permission schedules list checks. Existing protection switches, site exceptions, and recording preference remain intact.

What it does

FeatureBehavior
Common tracker blockingBlocks third-party requests to a small built-in list of advertising, analytics, and session-recording endpoints, plus two Facebook pixel patterns. Direct visits and first-party requests to those domains are left alone.
Known fingerprinting scriptsBlocks third-party requests to four listed fingerprinting endpoints. This does not disguise your fingerprint or intercept browser fingerprinting APIs. Some fraud checks may need these endpoints.
Link cleanupRemoves 22 specific tracking parameters, including common utm tags, gclid, fbclid, and msclkid, before a top-level GET navigation reaches the destination. It leaves POST forms, API calls, and unrecognized parameters alone. Parameter names are case-sensitive. It does not rewrite links in page text or erase stored history. Signed links that contain these tags may break; pause that destination if needed.
Third-party cookie filteringOptional and off by default. Removes outgoing Cookie and incoming Set-Cookie headers on requests classified by the browser as third-party relative to the initiating frame. This is not comprehensive cookie blocking: embedded frames can make requests that are first-party relative to themselves, and JavaScript-set cookies are not intercepted. Use your browser’s own cookie controls for broader restrictions. This switch may disrupt sign-ins or embedded content.
Site exceptionsPause protection for a hostname and its subdomains. After reloading, the exception also covers requests in nested frames. Resuming a parent-domain exception resumes its subdomains too.

If a website stops working

Open LocalGuard on that website, choose Pause on this site, then reload the page. To reverse it, choose Resume protection on this site and reload again. If cookie filtering was enabled, try turning it off. Site pausing uses the hostname shown in the popup; pausing www.example.com does not automatically pause example.com.

The main switch pauses all LocalGuard rules. The optional cookie filter and each other feature have separate switches. Pausing LocalGuard does not disable protections supplied by your browser or other extensions.

See proof of activity

Version 1.1 adds an Activity & audit view. Open the shield icon on a website to see how many blocked requests are retained for that tab, then choose View activity & audit. It shows actual browser-reported events across all tabs, with timestamps, destination domains, request origins, and matched rules. Filter by blocked requests, link-cleaning matches, or cookie-filter matches. Use Export audit JSON to save a report locally.

The log retains at most 500 events across all tabs in the current browser session. Counts are based on retained events and can decrease when older events leave the buffer. They are not lifetime totals or unique-tracker counts. A cookie-filter match does not prove a cookie existed; a link-cleaning match is not a count of parameters removed. The request origin is the initiating frame when available, which can differ from the top-level website.

Recording is on by default. Turning it off clears retained activity and leaves blocking unchanged. Its on/off preference is saved. Activity itself clears on browser exit, extension reload, or Clear activity; private-window events and requests without an associated tab are not recorded. No paths, query values, cookie contents, or passwords are retained. An exported report remains on your device until you delete it.

How to check it is working

  1. Make sure protection and activity recording are on.
  2. Open or reload a website, then open LocalGuard and choose View activity & audit.
  3. Look for Blocked request rows with a timestamp and destination domain. Those rows come from browser rule-match events, not from the number of rules installed.
  4. To compare, clear the log, pause that website, reload it, and check that new blocks from that page stop. Resume protection and reload when finished. Other tabs may still generate events.

A zero count is normal on pages that do not contact a listed tracker or where another privacy tool blocks requests first. The header saying protection is on means rules are enabled; the activity log provides evidence of individual actions. There is no claim that every tracker is detected. This audit capability requires a manually loaded, unpacked extension with Developer mode; it is not intended as a Web Store build.

Privacy and permissions

LocalGuard makes no telemetry, analytics, account, or subscription requests. When automatic updates are on, or you request a manual check, it downloads a public filter list. The distribution server sees your IP address and ordinary connection information, but receives no cookies, referrer, or browsing log from LocalGuard. It saves your switches, recording preference, paused hostnames, current/previous list snapshots, and update status in local extension storage. It retains a limited domain-only activity log in browser-session memory as described above. It does not store page content or passwords, and it does not upload your data.

  • Website access: HTTP and HTTPS access lets browser rules clean navigation URLs and filter cookie headers across sites. The browser may show a broad warning for this permission. The extension has no page content scripts.
  • declarativeNetRequest: lets the browser apply blocking, redirect, and header rules without inspecting page or cookie contents.
  • declarativeNetRequestFeedback: enables browser-issued rule-match events for this unpacked extension. The browser supplies request URLs; LocalGuard immediately reduces them to hostnames before retaining activity.
  • storage: saves settings locally and domain-only activity in session memory.
  • alarms: schedules hourly checks for the daily list update.
  • activeTab: lets the popup identify the website you are currently viewing for its pause control.

What it cannot replace

LocalGuard does not provide comprehensive fingerprint masking (canvas, WebGL, audio, fonts, or hardware), hide your IP address, stop first-party or server-side tracking, prevent identification while signed into an account, remove existing cookies, provide private email, protect other applications, or change Windows tracking settings. It is not antivirus or a VPN. Browser-internal pages, extension stores, and some browser-managed traffic cannot be protected by ordinary extensions.

The original built-in list is a limited, manually selected snapshot from September 14, 2026. The maintained EasyPrivacy subset supplements it with daily updates, but does not implement every EasyPrivacy filter or every tracking defense. It can miss trackers or block legitimate functionality. No independent privacy/security audit has been performed. It is independently authored and is not affiliated with any commercial security company.

Update or remove

To update, replace the files in the same folder with a reviewed newer version, then click Reload on its Extensions page card. Existing protection settings are retained. For version 1.2, accept added activity-reporting or scheduling permissions if prompted. Do not delete or move the loaded folder while using the extension. To uninstall, choose Remove on the Extensions page; its rules and extension storage will be removed with it. Developer-mode extensions may produce browser reminders.
